# examples/: worked examples from projects that ran on the harness

Each file here is one project's own account of how it used the method: an explainer written for its
collaborators, a hand-off, a ledger excerpt. They are kept as the project wrote them, with its field, its model
names, its numbers and its machine in place. Read them to see what the rules look like when they are lived in,
and to find the METHODOLOGY sections a passage illustrates: each file's header lists them.

What they are not: rules. Everything project-specific in an example (the field, the agent counts, the models and
their effort settings, the output budgets, the names of ledger rows, the machine, the status words where they
differ from the glossary's) is an illustration of a choice one project made under its own RESOURCES.md, not a
default of this harness. The rules live in METHODOLOGY.md and are cited by number; where an example and a rule
seem to differ, the rule governs, and the difference is worth a line in the example's header.

and for whom; which METHODOLOGY sections it illustrates), one row in this table, and a CHANGELOG.md entry.
Nothing here is edited after it is added; a correction is a new dated file.
