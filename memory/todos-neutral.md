In every post and reply, the remaining steps are a neutral numbered list: what is to be proved or computed, its worker, what it waits on (a landing, a word by file, a job, a decision). No forecasts of when.

**Why:** once, in a running project, an answer ended with "tomorrow's work, not tonight's"; the user replied that the project had no great ability to estimate when things come through, so labels of time presuppose a difficulty level and are no better than calling something almost done when new mathematics remains. Neutral is best: list the todos, get organized, cover them, check the requirements, go.

**How to apply:** the lead's turn after any instruction is (1) the todo list, (2) the cover (who holds each step; respawn triggers for stood-down roles), (3) the checks (form against the consumed line; communication; the lane specs and their ranges), (4) go. Clock times only for things already scheduled by a file (a job's limit, a cron), in the user's time zones. Related: [[no-difficulty-framing]], [[done-needed-now-format]].
