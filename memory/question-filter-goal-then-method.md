Run two filters, in order, before any question to the user or a co-author: (1) write the project goal in one line and test the question against it; (2) find the methodology rule that covers the case and quote it to yourself. Ask only when neither decides it, and say in the question why they do not.

**Why:** once, in a running project, the lead posed "which of two parametrizations" and "does a certificate without its error bound count as named" as decisions for the co-author. The goal (existence at one fixed parameter) settled the first; a rule already on file settled the second. The co-author's standing answer was: if it changes no final theorem and adds no hypothesis, decide it yourself and report. Earlier question lists had drawn a "why now".

**How to apply:** a question survives the filter only if it changes the statement of a final result or adds a hypothesis to one, or if it is a research-direction call the user has reserved. Otherwise apply the strict reading of the rule, state in one line what you decided and that the final theorems are untouched, and record it as a ruling. Owners and coordinators apply the filter before forwarding; the lead applies it again before sending. Related: [[never-idle-next-useful]], [[questions-plain-format]].
