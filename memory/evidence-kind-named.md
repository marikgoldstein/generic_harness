An evidence word without its kind reads as a contradiction next to a "proved" word. Say which of three kinds the item is: (a) open mathematics with a located step; (b) a computed input whose error certification is incomplete; (c) a reading of a printed line still to be quoted. For (b), state what is proved, what number is missing, the options, and who decides.

**Why:** once, in a running project, statuses said "last open math done" for an item and, in the same breath, that a certified bound was "not reachable". Both were true of different kinds: the chain was proved in letters, while one number's certified error was a thousandfold overestimate, so the tight error was empirical. The user could not follow until the kinds were named.

**How to apply:** when an owner proposes a class change (a number from computed to open mathematics, or back), tell the user the same hour with the kind named and "proposed, under review until the coordinator's class", and staff the dedicated prover the same turn; never let a "nothing open" line stand uncorrected past the next status. A truth word about a quantity's size is never drawn from a bound in the wrong direction. Related: [[open-but-algorithmic-class]], [[route-refuted-close-route-not-item]].
