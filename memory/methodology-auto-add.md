Whenever the user or a co-author says how to work (process, roles, gates, staffing, review, literature, numerics, wording), write it as a rule into METHODOLOGY.md in the same turn and tell them which rule it became.

**Why:** once, in a running project, two large working rules (the numerics gate and the wide literature sweep) were lost at a restart because they lived only in chat. The co-author then asked for one permanent, problem-agnostic rules file and said adding to it should be automatic; a bracketed tag in a message would only be a reminder.

**How to apply:** rules only, one per instruction; item-specific logistics are not rules, the general lesson behind them may be. New rules get new numbers under the right section; a retired rule is marked RETIRED in place. When the user asks "did you read the method file?", the answer should already be the rule number.
