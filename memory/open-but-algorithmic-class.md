An input whose own argument is proved and paired, and whose remaining content is a certified computation guaranteed to succeed given enough compute, is OPEN BUT ALGORITHMIC. An input that needs a new argument is OPEN MATHEMATICS. A named computation whose fit is not yet shown is neither. Every status prints "open: algorithmic a / mathematics m" per item and in total.

**Why:** once, in a running project, the words "named computation" and "open mathematics" did not tell the co-authors which open items were a matter of compute time and which still needed an argument; a status that said "last open math done" and "a certified bound is not reachable" in the same breath read as a contradiction. The co-author named the new class, since it is guaranteed to close.

**How to apply:** the closing rule is unchanged (an algorithmic input keeps its item OPEN until its value lands and fits); the class word only says what kind of wait it is. An owner's algorithmic list names computations only, never a reading or a form word. Related: [[closed-means-criteria-hold]], [[evidence-kind-named]], [[status-algorithmic-vs-mathematics]].
