An item is CLOSED only when its own argument is proved and has passed its pair, and every remaining named input is proved, printed with page and line, certified with room at least ten times its error, or owned by another open item. An item whose own owner still holds any input, however well staffed, prints "OPEN: own inputs left x".

**Why:** once, in a running project, an item was booked "closed" while one input was a declared estimate; the user could not understand how something could be closed but not proved. Later another item was called closed while its own owner still had inputs to prove; the co-author said the closing rule covered only inputs already being worked out by other items. The count went up each time, and that was the honest count.

**How to apply:** CLOSED must hold continuously: the moment a named input has no owner or no live effort, the item prints OPEN with no grace period. A census move is booked only when every gate is met by a file on disk, named exactly. Before posting any "what gates the close" word, run the four tests (own argument proved; pair passed; inputs named under the criteria; every remaining input owned elsewhere) and say which fail. "Named computation" is not "discharged": the certified value must land and fit. Related: [[prove-not-reduce]], [[frozen-open-ledger]], [[open-but-algorithmic-class]].
