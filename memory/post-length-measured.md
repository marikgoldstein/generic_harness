name: post-length-measured
description: Where the channel has a length cap, measure every post by script before sending; write to a smaller budget from the first draft; split at a section boundary, never let the channel cut mid-sentence; one retry at most (7.12)
metadata:
  type: feedback
---

Build each post in a script that asserts its length in characters before the file is written. Aim for about 80 percent of POST_CAP_CHARS from the first draft: one line per open item, no sub-clauses in parentheses, item lines short. Above the cap, split at a section boundary into parts that each read whole.

**Why:** once, in a running project, the channel cut a status at its limit and the decisions line was lost; later a single status failed its own length check nine times and nothing was posted for forty-five minutes while the co-author asked "?" twice. Trimming an over-long draft cost more turns than writing a short one.

**How to apply:** never spend more than one retry on an over-length single post; split instead. When a status is late, post the parts as they pass rather than holding all of them. Never edit a post file in place (one in-place edit left a mixed-zone stamp); write a new file per draft. Related: [[status-count-first]], [[timestamps-from-clock]].
