A status lists per open item: Done; Open algorithmic (n): the certified computations and reviews with their gates; Open mathematics (m): each named input with its route state (no proved route / located / pool running / text and pair owed); Now. The header gives the totals.

**Why:** once, in a running project, the co-author read every status for one thing first: how much of what was open was mathematics (uncertain) versus certified computation (guaranteed to close). A prose status that tagged "(algorithmic)" inside sentences did not give that at a glance, and a status not posted at all was the worst outcome.

**How to apply:** build the status as parts by item group, each under POST_CAP_CHARS by the script's assert; start drafts well under the cap; a late status is never silently skipped (the state log names the slot it covers).
