The closure chain: prover text → two independent refuters, refute-first, reading the same target from both ends → a writer applies only the refuters' minors into a new version → one closure re-read of that version → the ledger line CLOSED with the evidence chain named. Statement-level fixes from the re-read become named clauses; a hypothesis-level change costs exactly one more re-read; editorial changes cost none.

**Why:** once, in a running project, an item had been declared closed from a table of row verdicts, each row confirmed by two lanes; nobody could transcribe it into a proof with a source per sentence, and it was reopened. The chain above, run on the next campaign's first line, took about two and a half hours from prover launch to CLOSED and produced a text that could be printed as it stood.

**How to apply:** no confirmation counts unless it postdates the text's last change; an outside model's agreement is a third voice, never a refuter; refuter specs can be generated mechanically from the prover spec (its files plus the prover output) when lanes are idle.
